# Копилка

Учёт дохода и трат, накопления на цель, корзина продуктов на неделю и заготовки. Обычная статическая страница: HTML, CSS и JavaScript без сборки и зависимостей.

## Что умеет

- **Обзор:** прогресс к цели и прогноз даты, итоги месяца (доход, траты, отложено), траты по категориям против лимитов, история по месяцам, успехи и провалы.
- **Операции:** ручной ввод, фильтры, смена категории. При смене категории запоминается правило для этого места.
- **Импорт выписки:** CSV из интернет-банка. Кодировка, разделитель и столбцы определяются автоматически, повторно загруженные операции пропускаются. Категории ставятся по вашим правилам, затем по названиям магазинов, MCC и категории банка.
- **Привычки:** средние траты по категориям, дни недели, топ мест, регулярные платежи, мелкие траты, кафе в пересчёте на дни домашней еды, сравнение с прошлым месяцем.
- **Корзина:** список продуктов с отметками и ценами, запись чека в траты.
- **Питание и вес:** рацион, порядок заготовок, рецепты, журнал веса с темпом набора.

## Где хранятся данные

Только в браузере (localStorage), на сервер ничего не уходит. У локальной версии и у GitHub Pages данные разные. Перенос между устройствами: «Настройки → Сохранить копию», затем «Загрузить копию» на другом устройстве. Копии (`*.json`) и папка `private/` в git не попадают.

## Запуск

- Локально: двойной щелчок по `Открыть Копилку.command` (нужен только python3, он есть в macOS).
- GitHub Pages: Settings → Pages → Deploy from a branch → `main`, папка `/ (root)`.

## Банковский API

Открытого API для выписок физлиц у российских банков сейчас нет: у Сбера и Т-Банка API выдают бизнесу и партнёрам. Стандарт открытых API Банка России для физлиц принят, но банки подключаются постепенно. Поэтому используется CSV из интернет-банка. Если банк откроет API, нужен будет небольшой сервер для ключей, а разбор и категории останутся теми же (`js/csv.js`, `js/categorize.js`).
